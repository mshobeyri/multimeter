# MMT partner / distribution prospect list — NL, BE, DE

**Product:** Multimeter (MMT) — Git-native API testing & automation ([mmt.dev](https://mmt.dev))  
**Goal:** Small software agencies/consultancies (≈5–50 people) that can **standardize MMT across multiple client projects** (channel fit), not only buy it for themselves.  
**Research date:** 2026-09-16  
**Method:** Public websites, LinkedIn company pages, Impressum/contact pages. Unverified fields marked **Not found**. No invented people, emails, or headcounts.

## Ranking logic (channel fit)

Ideal: **1 company → many client projects → repeated API/integration testing needs → founder/CTO can mandate tooling.**

| Priority | Meaning |
|---|---|
| **High** | Clear multi-client API/integration delivery; size roughly in band; technical decision-maker identifiable |
| **Medium** | Multi-client product/software studio with backends/APIs, or good fit with ownership/size caveats |
| **Low** | Strong tech fit but **too small**, **product-led**, or **verification gaps** |

## Suggested next steps

1. Start with **integration pure-plays** (#1–5): WeAreFrank!, ARCHERS, i8c, DATA Passion, HikoniQ — highest “1→many projects” multiplier.  
2. Parallel track **Amsterdam/Brussels boutiques** (#6–15) where founders/CTOs can mandate tooling quickly.  
3. For outreach, lead with **Postman collections → Git `.mmt` + CI (testlight)** and **OpenAPI import**, tied to their named service lines (API Management, koppelingen, composable commerce).  
4. Re-verify LinkedIn headcounts before sending (they drift); treat employee counts as approximate.
